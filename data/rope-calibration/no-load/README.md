# No-load rope-diameter calibration

Reproducible, tension-free calibration of the rope-diameter model used by the
rope calculator. Everything in this directory is generated by
`data/rope-calibration/calibrate_no_load.py`; the superseded load-aware
calibration in `data/rope-calibration/legacy-load/` is archived history
and is not used by the current model.

## Model

`x` is the dTex of the purchased thread, `n` the number of threads per strand
(strands are always 3), `D` the finished rope diameter in mm.

```
u = ln(x / 300)
v = ln(n)
D = exp(c0 + c1*u + c2*v + c3*u^2)
```

Objective: minimise `sum(((D_calc - D_measured) / D_measured)^2)` over the
training rows. Every aggregated row has weight 1. There is no load term,
no load weight and no recommended-load substitution.

| coefficient | fitted | published | relative deviation |
| --- | --- | --- | --- |
| `c0` | -0.88417560 | -0.88417560 | 1.86e-09 |
| `c1` | 0.63185449 | 0.63185449 | 1.09e-09 |
| `c2` | 0.54357475 | 0.54357476 | 2.80e-09 |
| `c3` | -0.06147005 | -0.06147005 | 1.01e-08 |

Fitted coefficients at full float precision (`coefficients.json` is

```

c1 = 0.6318544941078147

```

Maximum relative deviation from the published coefficients:
`1.01e-08`
(tolerance `1e-06`).

## Run

```bash
python3 data/rope-calibration/calibrate_no_load.py           # rebuild no-load/*
python3 data/rope-calibration/calibrate_no_load.py --check   # verify, write nothing
```

Requirements: Python 3.10+, `numpy`, `scipy`; no network access. The xlsx
cross-check uses a small standard-library reader, so `openpyxl` is not needed.

## Sample rules

1. Start from the 143 type-P measurements in `normalized.csv` (130 old + 13
   new; new rows are Excel rows 175-187).
2. Remove Excel rows 179, 180 and 181 (UNI-C 20D 22.22 dTex) from the working
   sample only. Rows 182 (n=2, 0.086 mm) and 183 (n=1, 0.050 mm) stay in.
   The source records are never deleted or modified.
3. Average identical thread + dTex + n. Identity is the barcode when present,
   otherwise the exact series, otherwise the manufacturer; different barcodes
   are never merged. A group is averaged only when `(Dmax - Dmin) / Dmin <= 15 %`.
   Skala 360 n=2 is averaged by explicit user decision even though its spread
   is 15.4 %; `averaging-log.csv` records both the spread and the decision.
   Each aggregated row has weight 1 and the raw values stay in the log.
4. Exclude Excel rows 95 (Skala 240 5x3, 0.825 mm) and 133 (Tera 30 2x3,
   1.000 mm) as pre-existing training exceptions. They stay in
   `cleaned_130.csv` and are marked in `training_128.csv`.
5. Objective and weights are those of the model section above.
6. LOFO over 22 thread families: the whole family (all constructions and
   repeats) is removed from training, the coefficients are refitted on each
   split, and metrics are row-weighted. N100 and poliestere 300 share one
   family; M702 and M782 share one family. Family grouping (LOFO) and
   duplicate grouping (averaging) are independent procedures.
7. Metrics: `RMSPE = sqrt(mean(rel^2))`, `MAPE = mean(|rel|)`, MAE and RMSE in
   mm, bias as the mean relative error and the mean signed error.

## Determinism and `--check`

The fit uses deterministic multi-start Levenberg-Marquardt with relative
residuals (sum of squares `1.006143243825`, optimality `3.81e-08`).
`--check` writes nothing and fails when:

- a fitted coefficient differs from the published value by more than `1e-6`
  relative, or a metric exceeds its tolerance;
- a regenerated CSV differs from the committed one byte-for-byte;
- a JSON artefact differs structurally or a number differs beyond tolerance;
- `threads_merged.xlsx` or `normalized.csv` no longer match their documented
  SHA-256 (these inputs must never change);
- the on-disk files no longer match `SHA256SUMS.json`.

The `versions.python/numpy/scipy` fields make the JSON hashes machine
dependent, so on a different BLAS/scipy build `--check` ignores those fields
and compares coefficients and metrics with the explicit tolerances above.

## Interpretation notes

- `training_128.csv` lists all 130 working rows: the first 128 are the
  training set, and rows 95 and 133 are appended with `inTraining=False` so
  the exclusions are visible without deleting the records.
- The three UNI-C rows are removed before grouping and averaging. Averaging
  first would give the same result: neither UNI-C group would pass the 15 %
  spread rule (78 % and 100 % spreads), so no UNI-C row is averaged.
- `diameterTolerance: 0.10` in `coefficients.json` is the calculator's
  relative diameter tolerance (10 %), not a fitting parameter.
- The load column in the source is retained for provenance only. The model
  is no-load, so load is not a regressor and not a weight. For an averaged
  row, `loadGrams`, `source` and `position` in `cleaned_130.csv` come from
  the first source row and are provenance metadata, not part of the mean.
- The residual surface is very flat, so the last eight or so digits of the
  coefficients depend on the optimiser; the published values are recovered
  to about `1e-8` relative, well inside the `1e-6` requirement. Seeding the
  optimiser with the published values is deliberately not done.
- The 22 families are the LOFO grouping; the averaging groups in
  `averaging-log.csv` are a separate duplicate-grouping procedure.
