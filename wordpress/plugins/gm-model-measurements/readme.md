# Glushkov Modelling — Model Measurements

WordPress-модуль для хранения и редактирования индивидуальных размеров
моделей в миллиметрах.

Версия: `0.1.0`.

Статус: черновая реализация для проверки и доработки.
Не считать готовой к установке на production.

## 1. Назначение

Модуль добавляет:

- единый массив размеров в метаданных модели;
- метабокс «Размеры модели»;
- отдельное поле габаритной длины;
- произвольный набор дополнительных измерений;
- серверную нормализацию и проверку данных;
- переключаемую обязательность длины при публикации;
- защиту используемых справочных записей;
- проверку родительских связей элементов.

Измерения являются данными модели:

- не зависят от выбранного профиля такелажа;
- не удаляются при изменении профиля;
- не являются временными результатами калькулятора;
- не наследуют значения от родительских элементов.

Отсутствие измерения означает «не указано», а не ноль.

## 2. Границы текущей реализации

Модуль не реализует:

- создание CPT и ACF-групп справочников;
- автоматическую миграцию `modellength`;
- синхронизацию с `modellength`;
- GraphQL-поле `measurements`;
- изменение MCP-инструмента `get_build_details`;
- отображение размеров на публичном сайте;
- подключение размеров к калькуляторам;
- полноценное редактирование размеров через REST;
- подтверждённую поддержку блочного редактора;
- хранение размеров в ревизиях модели.

Публичную карточку модели этот модуль не изменяет.

Согласованное поведение публичного интерфейса относится к следующему
этапу: в карточке остаётся масштаб, размеры открываются по кнопке
«Размеры модели».

## 4. Зависимости и предпосылки

В заголовке плагина указаны:

- WordPress 6.0 или новее;
- PHP 7.4 или новее.

Это заявленные минимальные версии, а не результат проверки
совместимости на соответствующих окружениях.

Необходимы:

- активный Advanced Custom Fields;
- зарегистрированный CPT модели;
- справочник видов измерений `measurement_defi`;
- справочник элементов `model_element`;
- заранее созданные ACF-поля справочников.

ACF Repeater не используется.

Основной файл проверяет наличие ACF и типов записей.
Полнота и корректность содержимого справочников проверяются
при их загрузке.

## 5. Настройка CPT модели

Тип записи модели намеренно не задан по умолчанию.

Нужно явно передать массив фактических идентификаторов CPT через:

- константу `GM_MODEL_MEASUREMENTS_POST_TYPES`;
- либо фильтр `gm_model_measurements_post_types`.

Значение должно быть непустым массивом строк.

Не используйте вместо CPT:

- GraphQL-имя типа;
- название раздела в административном интерфейсе;
- адрес страницы;
- предположительный идентификатор.

До настройки плагин показывает административное уведомление
и не регистрирует обработчики метабокса, сохранения и защиты
справочников.

Фильтры конфигурации необходимо подключить до `wp_loaded`
с приоритетом `20`.

## 6. Обязательность габаритной длины

Настройка:

```php
define('GM_MODEL_MEASUREMENTS_REQUIRE_OVERALL_LENGTH', false);
```

Значение `false` — режим подготовки:

- допускается сохранение без габаритной длины;
- проверка обязательной длины при публикации выключена;
- остальные проверки отправленного набора продолжают действовать.

После заполнения и проверки существующих моделей:

```php
define('GM_MODEL_MEASUREMENTS_REQUIRE_OVERALL_LENGTH', true);
```

Альтернатива — фильтр:

```text
gm_model_measurements_require_overall_length
```

Настройка должна быть логическим значением, не строкой.

В текущем коде обязательность применяется к статусам:

- `publish`;
- `future`.

Черновик допускает отсутствие длины.

Статус `private` этой проверкой пока не охвачен.

Включение настройки само по себе не обходит существующие модели
и не меняет их статусы.

## 7. Формат хранения

Ключ метаданных:

```text
_gm_model_measurements
```

Значение — один PHP-массив, передаваемый в WordPress Metadata API.
Это не JSON-строка.

Пример представления данных в JSON:

```json
[
  {
    "definitionCode": "overall_length",
    "valueMm": 960
  },
  {
    "definitionCode": "mast_diameter",
    "valueMm": 10.5,
    "target": {
      "kind": "mast",
      "id": "main_mast"
    },
    "note": "Измерено у пяртнерса"
  }
]
```

Значения примера условные.

Правила:

- `definitionCode` — стабильный код вида измерения;
- `valueMm` — положительное конечное число в миллиметрах;
- `target` отсутствует у измерений без элемента;
- `target.kind` — `mast` или `yard`;
- `target.id` — стабильный код элемента, не ID записи WordPress;
- пустое примечание не включается в нормализованную запись.

Метазапись отсутствует — функция чтения возвращает пустой массив.

Повреждённые данные или несколько метазаписей с этим ключом
возвращают ошибку, а не пустой набор.

## 8. Числа и дубликаты

Текстовые значения допускают десятичную точку или запятую:

```text
10
10.5
10,5
```

Не допускаются:

- ноль;
- отрицательные числа;
- единицы измерения внутри значения;
- разделители тысяч;
- экспоненциальная запись в текстовом вводе;
- бесконечные значения;
- логические значения вместо числа.

Уникальность измерения определяется сочетанием:

```text
definitionCode + target.kind + target.id
```

Для измерения без элемента проверяется уникальность
`definitionCode` без `target`.

Два диаметра разных мачт допустимы.
Два одинаковых измерения одной мачты — нет.

## 9. Справочники

Для чтения используются исходные PHP/ACF-имена полей,
а не GraphQL-имена.

Виды измерений:

```text
measurement_code
measurement_group
measurement_target_kind
measurement_description
measurement_sort_order
measurement_active
```

Элементы:

```text
element_code
element_kind
element_parent
element_description
element_sort_order
element_active
```

Название берётся из заголовка записи.

Загрузчик включает опубликованные записи, в том числе неактивные.

Поддерживаемые группы измерений:

```text
overall
hull
rig
armament
other
```

Поддерживаемые типы привязки:

```text
none
mast
yard
```

Родитель элемента нормализуется в:

- `parentDatabaseId`;
- `parentCode`.

Множественный родитель и циклы считаются ошибками.

## 10. Системное измерение overall_length

Системная запись должна:

- иметь код `overall_length`;
- относиться к группе `overall`;
- иметь `target_kind=none`;
- быть активной;
- быть опубликованной для участия в загружаемом справочнике.

Габаритная длина редактируется отдельно.
Добавление её в дополнительные строки запрещено.

Примечание без значения длины вызывает ошибку.
Это предотвращает незаметное удаление введённого текста.

## 11. Неактивные записи

Неактивный вид измерения или элемент:

- не предлагается для новых строк;
- остаётся видимым в ранее сохранённой строке;
- допускается к сохранению только без изменения такой строки.

Можно:

- оставить строку без изменений;
- удалить строку;
- заменить неактивные ссылки совместимыми активными.

Нельзя изменить значение или примечание, сохранив неактивную ссылку.

Если справочная запись удалена или её тип стал несовместим,
совпадение со старой строкой не отменяет ошибку.

## 12. Сохранение и ошибки

Форма отправляется вместе с обычным сохранением записи WordPress.

Обработчик проверяет:

- право редактирования модели;
- nonce;
- маркер присутствия формы;
- структуру набора;
- существование справочных кодов;
- совместимость типов;
- дубликаты;
- обязательность длины, если она включена.

Отсутствие формы не означает очистку размеров.

При ошибке валидации новый массив размеров не записывается.

Другие поля модели при этом могут сохраниться:
сохранение всей записи и размеров не является одной транзакцией.

Если публикация отклонена:

- для ранее неопубликованной модели сохраняется безопасный
  неопубликованный статус;
- ранее опубликованная модель может остаться опубликованной,
  если сохранённые размеры удовлетворяют включённым требованиям;
- при обязательной длине и некорректном сохранённом наборе
  используется статус черновика.

После записи выполняется повторное чтение размеров.

При неподтверждённой записи и отсутствии обязательной длины
предусмотрена попытка перевода модели в черновик.
Ошибка такого перевода также отображается администратору.

## 13. Несохранённый ввод

После ошибки отправленные поля временно сохраняются отдельно:

- для текущего пользователя;
- для конкретной модели;
- в transient с заданным сроком до суток.

Transient может исчезнуть раньше.
Это не резервная копия и не ревизия.

Уведомление позволяет скопировать исходную форму в JSON.

Текущее ограничение:

- метабокс показывает прежние сохранённые значения;
- ошибочные строки не восстанавливаются автоматически;
- успешное повторное сохранение формы очищает временную копию.

Перед повторным сохранением нужно сохранить нужный ошибочный ввод.

Автоматическое восстановление формы остаётся обязательной
доработкой интерфейса.

## 14. Защита справочников

Использование проверяется по:

- каноническим размерам настроенных CPT моделей;
- всем зарегистрированным статусам моделей, включая корзину;
- дочерним элементам справочника.

Используемой записи запрещено:

- менять стабильный код;
- менять типовую совместимость;
- удаляться;
- сниматься с публикации.

Для архивирования предусмотрен признак активности.

`overall_length` дополнительно защищён от отключения
и изменения системных свойств.

При повреждённом наборе размеров модели проверка использования
завершается ошибкой, а не предположением об отсутствии ссылок.

Поиск использования выполняет полный просмотр подходящих моделей.
Отдельного индекса ссылок нет.

## 15. Ограничения защиты

Текущую реализацию нельзя считать полной защитой всех путей записи.

Остаются ограничения:

- прямой SQL обходит обработчики;
- параллельные изменения могут пройти между проверкой и записью;
- программные изменения вне предусмотренных административных
  и REST-потоков требуют отдельного контроля;
- публикация запланированной записи фоновым процессом
  не имеет отдельной повторной проверки в этом модуле;
- REST поддерживает только проверку публикации
  по уже сохранённым размерам;
- ревизии не участвуют в поиске ссылок;
- снятие с публикации и удаление могут быть отклонены
  без отмены остальных изменений записи;
- фильтры метаданных не создают транзакцию для набора ACF-полей;
- проверка родителя при изменении поля не заменяет полную
  проверку справочной записи перед её публикацией.

Для блочного редактора установлено:

```text
__block_editor_compatible_meta_box = false
```

Поддержку блочного редактора нельзя считать реализованной.

## 16. Подготовка к установке

До установки на рабочий сайт:

1. Провести статическую проверку всего комплекта.
2. Сверить имена ACF-полей и фактический CPT модели.
3. Проверить обработку значений в metadata-фильтрах,
   включая экранирование и снятие слешей.
4. Доработать восстановление ошибочной формы.
5. Проверить все ограничения публикации.
6. Выполнить приёмку на отдельном тестовом окружении.
7. Подготовить резервную копию перед любыми изменениями production.

Проектное расположение:

```text
wordpress/plugins/gm-model-measurements/
```

Предполагаемое расположение установленного плагина:

```text
wp-content/plugins/gm-model-measurements/
```

Автоматическая установка и деплой в комплект не входят.

Рекомендуемая последовательность проверки:

1. Указать подтверждённый CPT модели.
2. Оставить обязательность длины выключенной.
3. Проверить чтение справочников.
4. Проверить сохранение на тестовых моделях.
5. Заполнить размеры существующих моделей вручную.
6. Включить обязательность длины.
7. Повторить проверки публикации.

## 17. Чек-лист ручной приёмки

### Загрузка и конфигурация

- [ ] Без ACF выводится понятное уведомление.
- [ ] Без CPT модели обработчики не включаются.
- [ ] Некорректный CPT не подменяется другим идентификатором.
- [ ] Оба справочника доступны.
- [ ] Все ожидаемые ACF-поля читаются.
- [ ] Метабокс работает в поддерживаемом редакторе.

### Нормализация

- [ ] Отсутствующая метазапись возвращает пустой набор.
- [ ] Повреждённая метазапись вызывает ошибку.
- [ ] Несколько метазаписей не объединяются молча.
- [ ] Дробная точка и запятая обрабатываются одинаково.
- [ ] Ноль, отрицательные и нечисловые значения отклоняются.
- [ ] Неизвестные поля и дубликаты отклоняются.

### Интерфейс

- [ ] Длина показана отдельно.
- [ ] Длину нельзя добавить второй строкой.
- [ ] Добавление и удаление строк работают.
- [ ] Элементы фильтруются по типу измерения.
- [ ] Несовместимый выбранный элемент не подменяется молча.
- [ ] Примечания сохраняются.
- [ ] Узкий экран и управление клавиатурой проверены.
- [ ] Несохранённый ввод можно восстановить без потери данных.

### Сохранение

- [ ] После повторного открытия значения совпадают.
- [ ] Ошибка одной строки не приводит к частичной записи массива.
- [ ] Запрос без полей метабокса не очищает размеры.
- [ ] Неверный nonce не меняет размеры.
- [ ] Автосохранение и ревизии не стирают размеры.
- [ ] Слеши, кавычки и многострочные примечания не повреждаются.
- [ ] Остальные поля модели сохраняют ожидаемое поведение.
- [ ] Ошибка записи метаданных корректно обрабатывается.

### Публикация

- [ ] Черновик сохраняется без длины.
- [ ] В режиме подготовки длина не блокирует публикацию.
- [ ] При включённой проверке публикация без длины отклоняется.
- [ ] Отложенная публикация проверена отдельно.
- [ ] REST не позволяет обойти включённое требование длины.
- [ ] Поведение опубликованной модели при ошибке проверено.
- [ ] Поведение статуса private согласовано.
- [ ] Программные и фоновые пути публикации проверены отдельно.

### Справочники

- [ ] Дубликаты кодов отклоняются.
- [ ] Используемый код нельзя изменить.
- [ ] Используемый тип нельзя сделать несовместимым.
- [ ] Используемую запись нельзя удалить или снять с публикации.
- [ ] Неактивную старую строку можно сохранить без изменений.
- [ ] Неактивную ссылку нельзя использовать в новой строке.
- [ ] Системный overall_length защищён.
- [ ] Связь main_topmast → main_mast сохраняется.
- [ ] Корневой элемент допускает отсутствие родителя.
- [ ] Самоссылка, цикл и множественный родитель отклоняются.
- [ ] Публикация справочной записи проверяется целиком.

## 18. Условия завершения этапа 4

Этап можно считать завершённым после того, как:

- подтверждён и настроен CPT модели;
- выполнена проверка согласованности модулей;
- устранены обнаруженные дефекты;
- реализовано восстановление ошибочного ввода;
- согласованы и проверены поддерживаемые пути публикации;
- выполнена ручная приёмка;
- результаты проверки зафиксированы в трекере.

Само наличие файлов не означает завершение этапа.

## 19. Следующие этапы

После приёмки WordPress-модуля:

1. Определить и реализовать GraphQL-контракт `measurements`.
2. Добавить вывод размеров в интерфейс сайта.
3. Расширить существующий MCP-инструмент `get_build_details`.
4. Сохранить `modelLength` как совместимое представление
