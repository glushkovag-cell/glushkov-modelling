# Astro: размеры модели и предзаполнение калькулятора такелажа

Этап 7, часть Astro. MCP и расчётные формулы профилей в этом объёме не
изменяются.

## Источник данных

`src/lib/wordpress.ts` запрашивает у WPGraphQL поле `measurements` в
`GET_ALL_MODELS_PAGE` и `GetModelBySlug`:

```text
measurements {
  code
  label
  description
  group
  valueMm
  target { kind id label }
  note
}
```

Тип и нормализация описаны в `src/lib/modelMeasurements.ts`. Порядок
измерений задаёт WordPress; Astro его не пересортировывает.

## Общий компонент

`src/components/models/ModelMeasurementsDialog.astro` — кнопка «Model
dimensions» и нативный `<dialog>`. Используется:

- в карточках списка моделей `/builds`;
- в избранных карточках на главной странице;
- в блоке Project Specs на странице модели.

Кнопка находится вне ссылки карточки и не вызывает переход. Диалог
показывает название модели, габаритную длину первой строкой, затем
остальные измерения по группам. Пустые значения и пустые группы не
выводятся. Подпись контекстного размера включает название элемента:
`Mast diameter — Mainmast`.

Диалог открывается через `showModal()`: удержание фокуса, Escape и
инертность фона обеспечивает браузер. Фокус возвращается на кнопку, прокрутка
фона блокируется. На узком экране диалог занимает ширину viewport без
горизонтальной прокрутки. Оформление использует переменные темы, поэтому
работает в светлой и тёмной теме.

Старый вывод `Length` в Project Specs удалён. Поле `modelinfo.modellength`
пока остаётся в GraphQL-запросе для обратной совместимости до этапа 8, но в
публичном интерфейсе не выводится.

## Адаптер такелажа

`src/lib/rigging/modelMeasurements.ts` содержит явное сопоставление:

| Код измерения CMS | Элемент CMS | Вход калькулятора |
| --- | --- | --- |
| `mast_diameter` | `fore_mast` | `measurements.mastDiameter.fore` |
| `mast_diameter` | `main_mast` | `measurements.mastDiameter.main` |
| `mast_diameter` | `mizzen_mast` | `measurements.mastDiameter.mizzen` |
| `bowsprit_diameter` | — | `measurements.bowspritDiameter` |
| `hull_width` | — | `measurements.hullWidth` |
| `gun_bore` | — | `measurements.gunBore` |

Правила:

- `mast_diameter` без элемента или с другим элементом не применяется;
  произвольный диаметр не выбирается.
- `overall_width` не подменяет `hull_width`.
- `overall_length` и остальные неизвестные коды не участвуют в расчёте.
- Неположительные, нечисловые и дублирующиеся значения не применяются и
  попадают в диагностику.
- Значения передаются как `valueMm` с `unitId: mm` и `basis: model`.
  Масштаб повторно не применяется.

Точка замера не входит в GraphQL-контракт `measurements`. Поэтому адаптер не
переписывает поле `Point` в форме, а интерфейс просит сверить его с
определением измерения в CMS.

### Ручная сверка точки замера

Принято решение пока оставить сверку ручной. Порядок:

1. Открыть диалог размеров модели и прочитать название и определение
   измерения (например, `Mast diameter at the partners`).
2. В калькуляторе проверить поле `Point` у соответствующего диаметра мачты.
   Оно берётся из профиля (`mastPoint`, у `traditional_plant` — `partner`) и
   предзаполнением не меняется.
3. Запускать расчёт только после подтверждения соответствия.

Ограничения ручной сверки:

- Подсказка в калькуляторе не блокирует расчёт.
- Для `bowsprit`, `hull-width` и `gun-bore` поля `Point` в форме нет: калькулятор
  читает их с фиксированными значениями `working_section`, `unknown` и
  `working_section` соответственно. Сверить и изменить точку для них через UI
  нельзя.
- В текущих данных CMS бушприт назван `Max bowsprit diameter`, тогда как профиль
  задаёт для него `working_section`. Это известное расхождение, требующее
  отдельного решения: привести определение в CMS к методике, изменить методику
  или добавить структурированную точку замера в контракт.

Полноценная автоматическая проверка возможна только после добавления
структурированного поля точки замера в справочник WordPress и GraphQL.

## Предзаполнение в калькуляторе

На странице `/tools/rigging-diameters` в шаге 2 добавлен выбор модели и
кнопка «Fill dimensions».

- Заполняются только размеры, явно сопоставленные адаптером; остальные поля
  очищаются, чтобы демонстрационные значения не были приняты за измерения
  модели.
- Масштаб берётся из `modelinfo.modelscale`, если строка однозначно
  разбирается (`1:64`, `1/48`, `64`). Иначе масштаб не меняется и об этом
  сообщается.
- Наличие рангоута, профиль, версия профиля и формулы не меняются.
- Пустые обязательные поля подсвечиваются существующим механизмом
  `syncRequiredDimensions()`, а сообщение перечисляет оставшиеся обязательные
  входы.
- Расчёт автоматически не запускается: пользователь нажимает
  «Calculate diameters».

контрактной регрессии.
