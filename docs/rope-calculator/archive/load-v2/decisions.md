# Калькулятор канатов: учёт груза — аудит и решения

Задача: «Калькулятор канатов: учёт груза, ручной и автоматический режимы —
отчёт и ТЗ» (Glushkov Modelling Tasks Tracker, отчёт от 2026-11-16).
Доработка касается только калькулятора канатов. Калькулятор исторических
диаметров такелажа, OAuth, ACF и каталог CMS не меняются.

## Аудит текущего состояния (до доработки)

| Слой | Путь | Состояние |
| --- | --- | --- |
| Расчётное ядро | `rope-calculator-worker/src/core` | `calculateDiameterMm(dtex, n)`, без груза |
| HTTP | `rope-calculator-worker/src/http/app.ts` | `/api/rope/v1/{health,catalog,forward,reverse}` |
| Каталог | `rope-calculator-worker/src/catalog` | WPGraphQL → `caches.default`, TTL 86400 |
| UI | `src/widgets/rope-calculator` | Web Component `gm-rope-calculator`, API v1 |
| Страница | `src/pages/tools/rope-calculator.astro` | компонент и боковые плашки |
| MCP | `mcp-server/src/lib/rope-api.ts`, `tools/calculate-rope-diameter.ts`, `tools/find-rope-threads.ts` | адаптер к Worker v1 |

Действующий контракт: `apiVersion = "1"`, `algorithmVersion = "2.0.0"`,
формула `0.0204055952 × dtex^0.5293147610 × n^0.5366123919`, n = 1–5,
ручной dTex 80–6000, допуск обратного подбора ±15% включительно.
Кеша расчётных ответов нет: кешируется только каталог.

Снимок legacy-контракта: `docs/rope-calculator/fixtures/legacy-v1-snapshot.json`
(генератор `scripts/rope-legacy-snapshot.mjs`). Снимок сделан на коде до
доработки и служит базой для отчёта drift.

Пуш в `main` автоматически деплоит Worker, MCP и сайт в production; staging
нет. Поэтому доработка ведётся в ветке `feat/rope-load-v2`, слияние и
production-деплой — только после отдельного разрешения.

## Решения, подтверждённые на ревью (2026-11-17)

1. Формула «степенная + фактический вес»: `D = A × x^b × n^c × (w/200)^γ`.
2. Единый набор коэффициентов для ручного и автоматического режимов:
   `A = 0.015783234759902807`, `b = 0.5592028655918567`,
   `c = 0.5097503439652015`, `γ = 0.27528238252976955`.
   Набор не выбирается по `loadMode`.
3. Грузы: 30, 50, 100, 150, 200, 250, 300 г. Автоматический груз — по
   фиксированным порогам `S = 3·x·n`; на пороге выбирается верхняя ступень:

   | S | Груз, г |
   | --- | --- |
   | S < 150 | 30 |
   | 150 ≤ S < 250 | 50 |
   | 250 ≤ S < 400 | 100 |
   | 400 ≤ S < 550 | 150 |
   | 550 ≤ S < 650 | 200 |
   | 650 ≤ S < 800 | 250 |
   | S ≥ 800 | 300 |

4. Версии: API v2 (`/api/rope/v2/*`), `algorithmVersion = "3.0.0"`,
   `loadRecommendationVersion = "1.0.0"`. API v1 / алгоритм 2.0.0 остаются на
   переходный период и помечаются устаревшими.
5. Ручной dTex в v2: 20–6000 (включает измеренные 22.22, 33.33, 40). В v1
   остаётся 80–6000.
6. Допуск обратного подбора ±10% включительно — и в v2, и в v1. Для v1 это
   осознанное изменение контракта, отражённое в документации и тестах.
7. Точность: HTTP API отдаёт полные числа. UI выводит диаметр с 3 знаками,
   отклонение с 2 знаками без «−0.00%». MCP в новой реализации отдаёт
   диаметр с 3 знаками и отклонение с 2 знаками.
8. Автоматический груз — стартовая эмпирическая рекомендация, а не
   оптимальная или безопасная нагрузка. Промежуточные 50/100/150/250 г
   экспериментально не проверены.

Исходные измерения не меняются: dTex каталога CMS и измерительной таблицы
остаются разными источниками.

## Статус

Все решения реализованы в ветке `feat/rope-load-v2` (см.
[release.md](./release.md) и [drift.md](./drift.md)). Production-деплой не
выполнялся.
