# Откат

## 1. Что именно откатываем

| Симптом | Что откатывать |
| --- | --- |
| Калькулятор падает с ошибкой API | Worker |
| Каталог отдаёт старые данные | ничего: кеш живёт до 24 часов |
| Калькулятор не появляется в статье | статью и сборку сайта |
| Всё сломалось целиком | статью, затем Worker |

## 2. Worker

```bash
cd rope-calculator-worker

# посмотреть историю версий
npx wrangler deployments list

# откатить на предыдущую (нужен CLOUDFLARE_API_TOKEN и CLOUDFLARE_ACCOUNT_ID в окружении)
npx wrangler rollback
```

Альтернатива без `wrangler` на машине: вернуть коммит в `main`
(`git revert`) и запустить **Deploy rope calculator worker** — воркфлоу
задеплоит предыдущий код.

Каталог и кеш при откате кода не меняются: данные CMS те же.

## 3. Домен API

Если нужно снять публичный адрес, убрать `routes` из `wrangler.jsonc` или
поставить `workers_dev: false` без маршрута и задеплоить снова. Удаление
воркера (`npx wrangler delete`) освобождает и домен, но тогда калькулятор
перестанет работать полностью — это крайняя мера.

## 4. Статья

1. WordPress → статья → **Revisions** → выбрать версию до правки.
2. Пересобрать сайт: push в `main` или **Actions** → **Deploy to VPS** →
   **Run workflow**.
3. Проверить, что старый калькулятор снова работает и что новых ошибок в
   консоли нет.

## 5. Кеш каталога

Кеш `caches.default` локален для дата-центра и живёт до 24 часов. После правки
каталога в CMS API может отдавать старые данные до истечения TTL — это
ожидаемое поведение, а не дефект. Если данные нужно обновить немедленно:

- временно изменить версию схемы в ключе кеша
  (`CATALOG_CACHE_KEY` в `src/catalog/cache.ts`) и задеплоить;
- или подождать TTL.

## 6. Проверка после отката

- [ ] `GET /api/rope/v1/health` отвечает `ok: true`.
- [ ] `GET /api/rope/v1/catalog` отдаёт 23 нити.
- [ ] На странице статьи ровно один калькулятор и он считает `0.963 mm`.
- [ ] В консоли браузера нет ошибок.
