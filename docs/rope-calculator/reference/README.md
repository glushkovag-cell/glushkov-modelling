# Эталонная реализация калькулятора

`RopeCalc.html` — исходный одностраничный калькулятор, который заменяется
Worker-версией. Файл сохранён без изменений как **исторический** эталон
поведения: он описывает формулу замороженного контракта v1 (алгоритм 2.0.0), а
не актуальную модель 4.0.0. Актуальный источник истины — код Worker'а
(`src/core/model.ts` и `src/core/constants.ts`); см. `../model.md`.

- sha256: `e35333eded393c9307b6e3ce9b6594db7cb49a95ecc3ce5200fe748e4d51af70`
- 750 строк, зависимостей нет, каталог из 9 нитей встроен в скрипт.

## Почему файл не редактируется

Из него программно извлекаются только исторические значения baseline:

- выражение из `function diameterByDtex(dtex, threads)` — прежняя формула
  2.0.0, сохранённая в `fixtures/reference.json`;
- список `THREAD_CATALOG` — 9 эталонных нитей;
- константа `MAX_DEVIATION = 0.15` — прежний допуск эталона (текущий Worker
  использует ±10%, см. `spec.md`, разделы 6 и 13);
- правило вывода почти нулевого отклонения (`|pct| < 0.005` → `0.00%`).

Текущие коэффициенты и константы берутся из кода Worker'а, поэтому файл больше
не является источником истины для расчёта. Любая правка файла сдвинет
исторические эталонные значения. Если поведение нужно изменить намеренно, это
делается в спецификации и коде Worker, а не в этом файле.

## Как пересобрать фикстуры

```bash
# Проверить golden-таблицу, снимок CMS и исторический baseline
node scripts/gen-rope-fixtures.mjs

# Обновить снимок каталога из WordPress (нужны WP_GRAPHQL_URL и WP_GRAPHQL_SECRET)
node scripts/gen-rope-fixtures.mjs --catalog

# Проверка без записи: упадёт, если фикстуры разошлись с кодом воркера
node scripts/gen-rope-fixtures.mjs --check

# Пересобрать исторический reference.json из RopeCalc.html (меняет baseline!)
node scripts/gen-rope-fixtures.mjs --legacy-reference
```

Скрипт читает коэффициенты и константы из кода воркера (`src/core/model.ts`),
печатает модель, покрытие каталога и таблицу дрейфа к историческому baseline.
Секреты читаются из окружения или из `.env` в корне репозитория.
