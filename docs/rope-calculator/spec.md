# Калькулятор канатов — спецификация v1 и v2

Статус: этап 1 плана разработки — контракты, допуск и эталонные значения.
Реализация: этапы 2–6. Версия API — `v1`, версия алгоритма — `2.0.0`.

С задачи «учёт груза» основной контракт — `v2` (алгоритм `3.0.0`, рекомендация
груза `1.0.0`), см. [раздел 16](#16-api-v2-учёт-груза). `v1` остаётся
доступным для совместимости и считается устаревшим (раздел 17). Допуск
обратного подбора в обеих версиях — ±10%.

## 1. Назначение

Калькулятор оценивает диаметр трёхпрядного каната по линейной плотности нити и
числу нитей в пряди, а также подбирает нити каталога под целевой диаметр.
Расчёт и каталог живут только в Cloudflare Worker. Frontend и MCP-сервер
обращаются к JSON API и не дублируют ни формулу, ни данные.

## 2. Источники истины

| Что | Где | Примечание |
| --- | --- | --- |
| Формула и эталонное поведение | `docs/rope-calculator/reference/RopeCalc.html` | sha256 `e35333eded393c9307b6e3ce9b6594db7cb49a95ecc3ce5200fe748e4d51af70` |
| Каталог нитей | WordPress CMS, CPT `rope_thread`, ACF-группа `ropethreadfields` | читается только через WPGraphQL |
| Эталонные значения | `docs/rope-calculator/fixtures/reference.json` | 27 конструкций, сгенерированы из эталона |
| Снимок каталога | `docs/rope-calculator/fixtures/catalog-snapshot.json` | 69 конструкций и `catalogVersion` |

Фикстуры генерируются скриптом `scripts/gen-rope-fixtures.mjs`, который
извлекает выражение из функции `diameterByDtex()` эталонного файла. Вручную
формула ни в скрипте, ни в тестах не переписывается.

## 3. Алгоритм

```txt
D = 0.0204055952 × dtex^0.5293147610 × n^0.5366123919
```

- `D` — расчётный диаметр каната в миллиметрах.
- `dtex` — линейная плотность нити.
- `n` — число нитей в одной пряди: от 1 до 5.
- Прядей всегда три. Конструкция `2 × 3` передаёт в формулу `n = 2`, а не 6.

Расчёт выполняется в `float64` без промежуточного округления. Округление
допустимо только при отображении. Коэффициенты и версия алгоритма хранятся в
коде Worker (`algorithmVersion`), а не в ACF: правка коэффициентов — это
изменение поведения, а не контента.

История версий алгоритма:

- `2.0.0` — коэффициенты перекалиброваны по расширенной выборке, `n` расширен до 1–5.
- `1.0.0` — `D = 0.01752 × dtex^0.5437 × n^0.5880`, `n` = 1–3.

## 4. Валидация входов

| Поле | Правило |
| --- | --- |
| `basis` | `catalog` или `dtex`; для `catalog` обязателен `threadId`, для `dtex` — `dtex` |
| `dtex` (ручной ввод) | конечное число от 80 до 6000 включительно |
| `dtex` (каталожный) | принимается как есть; диапазон 80–6000 к нему не применяется |
| `threadsPerStrand` | одно из значений 1, 2, 3, 4, 5 |
| `threadId` | непустая строка, существует в каталоге и `enabled` |
| `targetDiameterMm` | конечное число больше нуля |
| `threadIds` | массив непустых строк; поле отсутствует — проверяются все активные нити; пустой массив — ошибка 422 |

Диапазон ручного ввода расширен до 6000, потому что в каталоге есть нити
3750 и 6000 dTex. Для каталожных значений проверка диапазона не применяется:
иначе две существующие нити стали бы нерабочими.

## 5. Прямой расчёт

`POST /api/rope/v1/forward`

```json
{ "basis": "catalog", "threadId": "tera-40", "threadsPerStrand": 2 }
```

```json
{ "basis": "dtex", "dtex": 750, "threadsPerStrand": 2 }
```

```json
{
  "apiVersion": "1",
  "algorithmVersion": "2.0.0",
  "catalogVersion": "0b24290aff0e",
  "fetchedAt": "2026-10-27T06:00:00.000Z",
  "basis": "catalog",
  "input": { "threadId": "tera-40", "dtex": 750, "threadsPerStrand": 2 },
  "result": {
    "diameterMm": 0.9842333087830643,
    "threadsPerStrand": 2,
    "strands": 3,
    "construction": "2 × 3"
  }
}
```

Для `basis: "dtex"` поля `catalogVersion` и `fetchedAt` равны `null`, CMS не
вызывается, отказ каталога не влияет на результат.

## 6. Обратный подбор

`POST /api/rope/v1/reverse`

```json
{ "targetDiameterMm": 1.0, "threadIds": ["tera-40", "tera-60"] }
```

Отклонение считается как `deviation = (D - target) / target`, в ответе —
`deviationPercent = deviation × 100`. В выборку попадает вариант при
`|deviation| ≤ 0.10` — граница включительная. До перехода на v2 допуск был
±15% (`0.15`, как в эталоне `RopeCalc.html`); сужение до ±10% согласовано
для обеих версий API и намеренно расходится с эталоном.

Сортировка результатов, по возрастанию:

1. `|deviation|`
2. `dtex`
3. `threadsPerStrand`
4. `sortOrder`
5. `threadId`

Последние два ключа нужны из-за неизбежных дублей: `mara-15`/`tera-15` (2000), `mara-30`/`tera-30` (1000) дают одинаковые
диаметры. Без дополнительных ключей порядок зависел бы от порядка входа.

Смешивание разных нитей в одной конструкции не поддерживается. Отсутствие
совпадений — успешный ответ `200` с пустым `results`, а не ошибка.

```json
{
  "apiVersion": "1",
  "algorithmVersion": "2.0.0",
  "catalogVersion": "0b24290aff0e",
  "fetchedAt": "2026-10-27T06:00:00.000Z",
  "input": { "targetDiameterMm": 1.0, "tolerance": 0.1 },
  "results": [
    {
      "threadId": "mara-100",
      "brand": "Mara",
      "number": "100",
      "dtex": 300,
      "threadsPerStrand": 5,
      "construction": "5 × 3",
      "diameterMm": 0.990836685359095,
      "deviationPercent": -0.9163314640905029
    }
  ]
}
```

## 7. Форматирование в интерфейсе

API отдаёт полную точность. Округление — обязанность frontend:

- диаметр — три знака после запятой (`0.963`);
- отклонение — два знака в процентах со знаком (`+1.94%`, `-3.68%`);
- если `|deviationPercent| < 0.005`, выводится `0.00%` без знака — правило
  взято из эталонного файла, чтобы не появлялось `-0.00%`;
- единицы — `mm`, конструкция — `N × 3`;
- `brand` и `number` выводятся как строки из CMS без разбора в числа.

## 8. Каталог и версия

- В ответ попадают только опубликованные записи с `enabled = true`.
- Порядок: `sortOrder` по возрастанию, затем `threadId` по возрастанию.
- `number` — обозначение нити, а не расчётное число.
- `catalogVersion` — первые 12 hex-символов sha-256 от канонического JSON
  массива записей в порядке выдачи с полями `threadId`, `brand`, `number`,
  `dtex`, `sortOrder`, `enabled`. Добавление, удаление или правка любой записи
  меняет версию.
- `fetchedAt` — момент, когда каталог был прочитан из CMS и положен в кеш.

## 9. Ошибки

Единый формат:

```json
{
  "error": { "code": "INVALID_PARAMS", "message": "dtex must be between 80 and 6000", "fields": ["dtex"] },
  "requestId": "8f3c1a7b2e40"
}
```

| Код | HTTP | Когда |
| --- | --- | --- |
| `BAD_JSON` | 400 | тело не разбирается как JSON |
| `NOT_FOUND` | 404 | неизвестный маршрут |
| `METHOD_NOT_ALLOWED` | 405 | неподдерживаемый метод |
| `BODY_TOO_LARGE` | 413 | тело больше 8 КиБ |
| `INVALID_PARAMS` | 422 | тип, диапазон, `n` вне 1–5, пустой `threadIds`, `targetDiameterMm ≤ 0` |
| `THREAD_NOT_FOUND` | 422 | неизвестный или отключённый `threadId` |
| `CATALOG_UNAVAILABLE` | 503 | CMS недоступна и кеша нет |
| `CATALOG_INVALID` | 503 | каталог пуст, неполон или содержит дубли `threadId` |
| `INTERNAL` | 500 | прочие сбои |

## 10. Кеш каталога

- `caches.default` под фиксированным GET-ключом
  `https://rope-catalog.internal/v1?schema=1`; ключ не зависит от параметров
  расчёта.
- TTL — 86400 секунд через `Cache-Control: public, max-age=86400`.
- Кеш локален для дата-центра Cloudflare и может быть вытеснен раньше TTL.
  Требование — снизить частоту чтения CMS, а не гарантировать одно обращение
  в сутки.
- Ошибки, GraphQL-ошибки и неполный каталог в кеш не пишутся.
- Одновременные промахи схлопываются через `inFlight` Promise в пределах
  изолята; глобальной блокировки нет.
- KV, D1 и Durable Objects не используются.

## 11. Транспорт

- CORS: `https://www.glushkov-modelling.com`, `https://glushkov-modelling.com`,
  `http://localhost:4321`. Методы `GET`, `POST`, `OPTIONS`. Заголовок
  `content-type`. `Vary: Origin`. Preflight — `204`. Credentials не
  используются.
- Лимиты: тело ≤ 8 КиБ, таймаут CMS 5 с, общий таймаут запроса 10 с.
- `requestId` — из `cf-ray`, если заголовок есть, иначе случайный.
- Секрет CMS (`X-GraphQL-Secret`) хранится только в Worker Secrets. Endpoint
  CMS и GraphQL-запрос фиксированы в коде; клиент не может их подменить.
- Код `429` в v1 не используется: без хранилища общий лимит частоты
  нереализуем, защита от всплесков — правило Cloudflare на зоне.

## 12. Дефолты интерфейса

Режим — прямой расчёт; основание — каталог; нить — `tera-40`; нитей в пряди —
2; целевой диаметр — `1.00`; в обратном подборе отмечены все нити.

## 13. Известное расхождение с эталоном

Каталог CMS — источник истины, поэтому два значения отличаются от эталонного
файла. Расхождение зафиксировано тестом, а не устранено.

| Нить | Эталон | CMS | Отклонение диаметра при 3 × 3 |
| --- | --- | --- | --- |
| `skala-240` | 120 | 119 | −0.442% |
| `tera-10` | 3000 | 2900 | −1.778% |

Остальные нити эталона совпадают с CMS. Полное совпадение с исходным
калькулятором на всех конструкциях невозможно и критерием приёмки не является.

## 14. Вне области v1

- Пользовательская авторизация и OAuth для калькулятора.
- Серверный rate limiting (код 429).
- Стабильный URL бандла для сторонних страниц (`/widgets/.../v1.js`).
- Отдельная страница раздела Tools — только временная проверочная страница.
- Кеширование устаревшего каталога дольше TTL.

## 15. Встраивание

Скрипт подключён глобально в `src/layouts/BaseLayout.astro` и загружает
компонент только на страницах, где есть элемент, поэтому в статье достаточно
одного тега:

```html
<gm-rope-calculator>
  <noscript>Enable JavaScript to use the rope calculator.</noscript>
</gm-rope-calculator>
```

- `api-base` необязателен: по умолчанию `https://api.glushkov-modelling.com`.
  Внешним страницам его нужно передавать явно; адрес API не выводится из
  `location.origin`.
- `noscript` лежит в light DOM намеренно: без JavaScript элемент не
  апгрейдится и shadow DOM не создаётся, поэтому фолбэк обязан быть обычным
  потомком элемента, а не частью его разметки.
- Порядок загрузки: лоадер (~1 КБ gzip) на всех страницах, сам компонент
  (~5 КБ gzip) — отдельным чанком и только при наличии элемента.
- Внутри компонента нет ни формулы, ни каталога: только запросы к API.
  Проверяется поиском коэффициента формулы в собранном чанке.
- Временная проверочная страница `/rope-preview` закрыта `noindex` и исключена
  из sitemap; на этапе 6 её заменяет встраивание в статью.


## 16. API v2: учёт груза

Решения и обоснование — `docs/rope-calculator/load-v2/decisions.md`,
калибровка — `data/rope-calibration/` (воспроизводится
`python3 data/rope-calibration/calibrate.py --check`).

### 16.1 Модель

```txt
S = 3 × x × n
D = a × x^b × n^c × (w / 200)^k
a = 0.015783234759902807, b = 0.5592028655918567,
c = 0.5097503439652015,   k = 0.27528238252976955
```

- `x` — dTex исходной нити, `n` — нитей в пряди (1–5), `w` — груз в граммах.
- Один набор коэффициентов для ручного и автоматического режимов: при
  одинаковых `x`, `n`, `w` диаметр одинаков.
- Расчёт в `float64` без промежуточного округления.

### 16.2 Грузы и рекомендация

Допустимые грузы: 30, 50, 100, 150, 200, 250, 300 г. Испытаны только 30, 200 и
300 г; для остальных в ответ добавляется предупреждение `UNVERIFIED_LOAD`.

| `S` | Рекомендованный груз |
| --- | --- |
| < 150 | 30 |
| 150 – < 250 | 50 |
| 250 – < 400 | 100 |
| 400 – < 550 | 150 |
| 550 – < 650 | 200 |
| 650 – < 800 | 250 |
| ≥ 800 | 300 |

На пороге применяется верхняя ступень. Рекомендация — стартовое значение, а не
экспериментально установленный оптимум.

### 16.3 Валидация v2

| Поле | Правило |
| --- | --- |
| `loadMode` | `auto` или `manual`; отсутствие означает `auto` |
| `loadGrams` | при `manual` обязателен и входит в список 16.2; при `auto` или без `loadMode` запрещён |
| `dtex` (ручной ввод) | конечное число от 20 до 6000 включительно |
| `threadsPerStrand` | целое 1–5 |

Остальные поля — как в разделе 4. Ошибки — `422 INVALID_PARAMS` с `fields`.

### 16.4 Маршруты

| Метод | Путь |
| --- | --- |
| GET | `/api/rope/v2/health` |
| GET | `/api/rope/v2/catalog` |
| POST | `/api/rope/v2/forward` |
| POST | `/api/rope/v2/reverse` |

Каждый ответ содержит `apiVersion: "2"`, `algorithmVersion: "3.0.0"`,
`loadRecommendationVersion: "1.0.0"`. Для ручного dTex CMS не запрашивается,
`catalogVersion` и `fetchedAt` равны `null`.

### 16.5 Прямой расчёт

```json
{ "basis": "dtex", "dtex": 80, "threadsPerStrand": 2, "loadMode": "auto" }
```

```json
{
  "apiVersion": "2",
  "algorithmVersion": "3.0.0",
  "loadRecommendationVersion": "1.0.0",
  "catalogVersion": null,
  "fetchedAt": null,
  "basis": "dtex",
  "input": { "dtex": 80, "threadsPerStrand": 2, "loadMode": "auto", "loadGrams": null },
  "result": {
    "basis": "dtex",
    "threadId": null,
    "dtex": 80,
    "threadsPerStrand": 2,
    "strands": 3,
    "construction": "2 × 3",
    "totalDtex": 480,
    "loadMode": "auto",
    "recommendedLoadGrams": 150,
    "appliedLoadGrams": 150,
    "diameterMm": 0.24069446380613793
  },
  "warnings": [
    { "code": "EMPIRICAL_MODEL", "message": "..." },
    { "code": "RECOMMENDED_LOAD_STARTING_SUGGESTION", "message": "..." },
    { "code": "UNVERIFIED_LOAD", "message": "..." }
  ]
}
```

В режиме `manual` `appliedLoadGrams` равен выбранному грузу, а
`recommendedLoadGrams` всё равно возвращается — для сравнения.

### 16.6 Обратный подбор

```json
{ "targetDiameterMm": 1.0, "loadMode": "manual", "loadGrams": 200 }
```

- `auto`: груз рекомендуется отдельно для каждой пары «нить × n» по её `S`.
- `manual`: один груз для всех кандидатов; `recommendedLoadGrams` у каждого свой.
- Допуск ±10% включительно, фильтр по неокруглённому отклонению.
- Сортировка — как в разделе 6. Пустой результат — `200` и `results: []`.
- Каждый элемент `results` дополнительно содержит `totalDtex`, `loadMode`,
  `recommendedLoadGrams`, `appliedLoadGrams`.
- `input` содержит `tolerance: 0.1`, `loadMode`, `loadGrams` (`null` при `auto`).

### 16.7 Предупреждения

| Код | Когда |
| --- | --- |
| `EMPIRICAL_MODEL` | всегда |
| `RECOMMENDED_LOAD_STARTING_SUGGESTION` | всегда |
| `UNVERIFIED_LOAD` | применён груз 50, 100, 150 или 250 г (в прямом расчёте и в reverse `manual`) |
| `DTEX_OUTSIDE_MEASURED_RANGE` | dTex вне 22.22–3000 |

### 16.8 Округление

API отдаёт неокруглённые числа. Сайт и MCP показывают диаметр с тремя знаками,
отклонение — с двумя, без `−0.00`.

## 17. Устаревание v1

- `v1` продолжает работать без изменения формы ответов; единственное изменение
  поведения — допуск ±10% вместо ±15%.
- Сайт и MCP (при явном `loadMode`) используют `v2`.
- Удаление `v1` — отдельная задача после того, как внешних обращений не
  останется.
