## Дубли dtex

Каталог намеренно содержит пары с одинаковой линейной плотностью:

- `mara-80` / `mara-70` — 400;
- `mara-15` / `tera-15` — 2000;
- `mara-30` / `tera-30` — 1000.

Диаметры в таких парах совпадают, поэтому порядок результатов обратного
подбора задаётся ключами `sortOrder` и `threadId` (см. `spec.md`, раздел 6).

## Расхождение с эталонным файлом

`reference/RopeCalc.html` содержит 9 нитей. Семь совпадают с CMS по dtex,
две расходятся:

| Нить | Файл | CMS | Отклонение диаметра при 3 × 3 |
| --- | --- | --- | --- |
| `skala-240` | 120 | 119 | −0.454% |
| `tera-10` | 3000 | 2900 | −1.826% |

Решение от 27.10.2026: CMS остаётся источником истины, значения не
переписываются. Расхождение проверяется тестом, чтобы изменение данных было
заметным.

## Как добавить нить

1. Создать запись в CPT `rope_thread`, заполнить `threadId` (уникальный,
   латиница в нижнем регистре с дефисами), `brand`, `number`, `dtex`,
   `sortOrder`, включить `enabled`.
2. `sortOrder` должен продолжать порядок марки: Mara — 1xx, Skala — 2xx,
   Tera — 3xx, шаг 1.
3. Проверить, что `dtex` — положительное конечное число; диапазон 80–6000 не
   обязателен, но выходящее за него значение стоит подтвердить отдельно.
4. Обновить снимок и фикстуры: `node scripts/gen-rope-fixtures.mjs --catalog`.
5. Убедиться, что `catalogVersion` изменился, и закоммитить снимок вместе с
   правкой.
6. API подхватит новый каталог после истечения TTL кеша (до 24 часов) или
   после сброса кеша при следующем развёртывании.

## Как убрать нить

Снять `enabled` — запись исчезнет из API сразу после обновления кеша.
Удаление записи меняет `catalogVersion`, но ломает ссылки на `threadId`
в старых ответах и тестах, поэтому предпочтительно отключать, а не удалять.
