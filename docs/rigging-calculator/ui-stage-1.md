# Этап 1: навигация по ведомости такелажа

Реализация P0-этапа ТЗ «Доработки UI калькулятора такелажа».
Ветка: `feat/rigging-ui-hierarchy`. Расчётное ядро, профили и формулы не
менялись; контрольный снимок `tests/fixtures/rigging-control.json` совпадает.

## 1. Разделение данных и представления

- `src/lib/rigging/ledgerView.ts` — чистая проекция: строки, узлы, ярусы, виды
  такелажа, опции фильтров, поиск, подсветка, сортировка, счётчики.
- `src/lib/rigging/ledgerState.ts` — состояние просмотра и переходы: режим,
  фильтры, поиск, сортировка, свёрнутые секции, сброс несовместимого яруса,
  правила `Not applicable`, согласование с новым расчётом.
- `src/lib/rigging/threadPick.ts` — выбранная модельная нить строки.
- `src/scripts/riggingCalculator.ts` — только DOM и события; все решения о
  составе строк принимает модель представления.

Фильтрация, поиск, сортировка, смена режима и раскрытие не вызывают запрос к
API и не меняют входные данные. Проверено в браузере: число запросов
`/api/rigging/v1/calculate` не меняется при всех операциях просмотра.

## 2. Что появилось в интерфейсе

- Иерархия по умолчанию: узел → ярус → вид такелажа → строки.
  Фок-, грот- и бизань-мачта — отдельные секции; ярусы внутри мачты соседние;
  строки без яруса собраны в «No tier» последним разделом. Бушприт, якорная
  группа, орудия и `hull` (где он есть) — самостоятельные секции без
  искусственных ярусов и видов.
- Секции раскрываются нативно (`<details>`), при первом расчёте открыты.
  `Expand all` / `Collapse all` работают по видимым секциям и скрыты в плоском
  режиме. Во время поиска они остаются доступными: новый запрос раскрывает
  совпадения, а `Collapse all` / `Expand all` позволяют свернуть или раскрыть
  найденные группы вручную.
- Режимы `By node` / `Flat table`. В плоском режиме добавляются колонки
  `Node` и `Tier`; фильтры, поиск и подбор нити сохраняются при переключении.
- Колонки: `Rope`, `Model Ø`, `Material`, `Status`, `Thread`, `Details`.
  В плоской таблице — `Rope`, `Node`, `Tier`, `Model Ø (mm)`, `Material`,
  `Status`, `Thread`, `Details`. Детали строки в обоих режимах открываются
  кнопкой `Details`, а не кликом по строке.
- Сортировка: порядок профиля, имя A–Z / Z–A, диаметр по возрастанию / убыванию.
  В grouped-режиме сортируется каждая конечная группа, в flat — вся выборка.
  Строки без диаметра всегда последние.
- Фильтры `Node`, `Tier`, `Rigging type`, `Status` независимы, одиночный выбор
  + `All`, между собой и поиском — AND. Опции строятся из полной ведомости
  текущего расчёта.
- После выбора узла недоступные ярусы отключаются; выбранный несовместимый
  ярус сбрасывается с уведомлением. Если у узла нет ярусов, фильтр отключён и
  пояснён.
- `Rigging type`: `All` сохраняет бушприт, якоря и орудия; `Standing` /
  `Running` показывают только строки с подтверждённой классификацией. Правило
  объяснено рядом с фильтром.
- Поиск по RU и EN названиям одновременно: часть слова, без учёта регистра и
  е/ё, пробелы по краям игнорируются. Несколько слов должны найтись все в
  одном названии — английском или русском, а не вперемешку. Совпадения
  подсвечиваются текстовыми `<mark>`; ветви с совпадениями раскрываются.
- Активные условия показаны чипами с индивидуальным удалением, `Clear all`
  очищает поиск и фильтры, но не расчёт, подбор нити и режим. Счётчик
  `N of M`: `M` — строки расчёта с учётом `Show not applicable`, `N` — после
  поиска и фильтров.
- Пустые состояния различают отсутствие строк для конфигурации, отсутствие
  совпадений и полностью скрытые `not_applicable`; для выборки предлагается
  `Clear filters` или `Show not applicable`.
- Колонка Thread: `Pick thread` открывает существующий калькулятор канатов;
  в таблице результатов появилась кнопка `Use`, которая возвращает выбранную
  нить в строку. Выбор живёт в состоянии просмотра, переживает фильтры,
  сортировку, смену режима и пересчёт. Проверка актуальности нити после
  изменения целевого диаметра — этап 3.
- Состояние `не рассчитано / идёт расчёт / ошибка / устарело` не смешивается:
  старые результаты остаются, помечаются `is-stale`, экспорт отключается до
  пересчёта. Запоздалые ответы отбрасываются по номеру запроса.
- Доступность: нативные `summary`/`details` для секций, кнопки `Details`
  с `aria-expanded`/`aria-controls` для строк, `aria-expanded` у панели
  фильтров, текстовые статусы (не только цвет),
  подписи для скринридеров, видимый фокус, возврат фокуса из диалога подбора
  нити, `role="status"` у счётчика результатов.

## 3. Адаптивность

- 1280 и 768 CSS px — таблица/дерево с колонками.
- Не шире 900 px — строки дерева переходят в двухколоночную карточку;
  плоская таблица становится карточками с `data-label` для каждой колонки,
  включая `Node` и `Tier`.
- 390 и 360 — тулбар и фильтры в одну колонку, карточки без горизонтальной
  прокрутки. Проверено на 360, 390, 768 и 1280: `scrollWidth` контейнера
  ведомости не превышает `clientWidth`.

## 4. Локальная разработка и каталог нитей

Каталог нитей живёт на отдельном хосте `api.glushkov-modelling.com`. Его
allowlist содержит production-домены и `http://localhost:4321` (стандартный
порт `astro dev`), но не `127.0.0.1` и не другие порты. Расчётный API при этом
разрешает любой loopback-порт. Поэтому:

- при `npm run dev` на стандартном `http://localhost:4321` каталог работает;
- при `127.0.0.1` или другом порту браузер блокирует чтение каталога — это
  ограничение CORS среды, а не регрессия этапа;
- production-страница работает, allowlist содержит её origin.

Для локальной проверки на произвольном порту:

- `?api=http://127.0.0.1:PORT` — база расчётного API;
- `?rope-api=http://127.0.0.1:PORT` — база каталога нитей (нужен локальный
  прокси, добавляющий CORS).

Если каталог недоступен, виджет больше не показывает вводящее в заблуждение
«Select at least one available thread»: он остаётся в прямом режиме и
объясняет, что каталог недоступен и можно использовать custom dTex.

## 5. Проверки

- `npm test` — 163 теста, включая контрольный снимок, модель представления,
  состояние, поиск, сортировку, исчерпывающую матрицу фильтров, счётчики и все
  профили.
- `npx astro check` — 0 ошибок и предупреждений.
- `npm run build` — успешно.
- Браузерная проверка (Chrome headless, локальный CORS-прокси к тем же API):
  59/59 сценариев, 0 исключений; отдельно 10/10 инвариантов:
  - фильтры/поиск/режим/сортировка не вызывают расчёт;
  - подбор нити переживает фильтры, `Clear all` и пересчёт;
  - изменение ввода помечает результаты устаревшими и не запускает расчёт;
  - пересчёт снимает устаревание и добавляет ровно один запрос.
- Замер на полной ведомости 279 строк: смена узла/режима с полной перерисовкой
  — максимум ~14 мс на согласованном тестовом устройстве (Chrome, Apple
  Silicon). Подробности строк строятся лениво при раскрытии.
- Отдельно проверены замечания к этапу: подсказка поиска — `Search by name`
  без упоминания языка; при недоступном каталоге нитей виджет остаётся в
  прямом режиме и объясняет причину, без ложного «Select at least one
  available thread» (10/10 проверок).
