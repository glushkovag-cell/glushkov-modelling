# Этап 3: продолжительная работа

Реализация P2-этапа ТЗ «Доработки UI калькулятора такелажа».
Ветка: `feat/rigging-ui-hierarchy`. Расчётное ядро, профили и формулы не
менялись; контрольный снимок `tests/fixtures/rigging-control.json` совпадает.

## 1. Сохранение представления

- Состояние просмотра сохраняется в `sessionStorage` под версионированным
  ключом `rigging-ledger-view-v1`.
- Сохраняются: режим `Grouped` / `Flat table`, фильтры Node / Tier / Rigging
  type / Status, поиск, сортировка, область экспорта и свёрнутые секции.
- После перезагрузки страницы расчёт выполняется заново по текущей форме, а
  затем применяется сохранённое представление. Поиск появляется в поле, режим,
  сортировка и область экспорта восстанавливаются.
- Если сохранённый узел, ярус или статус больше не существуют в расчёте,
  `reconcileState` сбрасывает их с уведомлением и сохраняет уже исправленное
  состояние.
- Битое, устаревшее или недоступное хранилище не ломает страницу: используется
  состояние по умолчанию. Закрытая вкладка очищает представление; это
  сознательный выбор, чтобы старые фильтры не возвращались через дни.
- Конфигурация формы, результаты расчёта и выбранные нити в storage не
  сохраняются. Это ограничение описано ниже.

## 2. Контроль нитей после пересчёта

- Выбор нити хранится по стабильному ключу строки и привязывается к диаметру
  строки на момент выбора (`rowDiameterMm`) и к цели подбора (`targetMm`).
- После пересчёта выбор автоматически применяется к той же строке. Если
  диаметр строки изменился, нить помечается `Review`:

  - в колонке Thread появляется `Review · Ø … mm`;
  - подробности строки объясняют, с какого диаметра на какой изменился;
  - в статусе результатов появляется счётчик `N thread picks need review`;
  - выбор не удаляется и не подменяется молча.

- Повторный подбор обновляет диаметр строки и снимает пометку.
- Если нить подбирали для цели, отличной от диаметра строки, это также требует
  проверки.
- Если после пересчёта у строки вообще нет рассчитанного диаметра
  (`needs_input` / `unsupported`), нить помечается для проверки: старый выбор
  нельзя считать актуальным.

## 3. Экспорт всей ведомости и выборки

- В заголовке результатов появился выбор области: `All rows` или
  `Current selection`.
- `Current selection` использует ровно ту же выборку, что счётчик `N of M`:
  поиск, независимые фильтры и переключатель `Show not applicable`. Скрытые
  неприменимые строки в выборку не попадают.
- `All rows` экспортирует всю ведомость расчёта, включая скрытые
  неприменимые строки — это исследовательская ведомость, а не только список
  рассчитанных чисел.
- CSV содержит только выбранные строки; JSON дополнительно записывает
  `selection.scope`, `rowCount`, `totalRowCount` и текстовые условия выборки.
- Имя файла для выборки получает суффикс `-selection`.
- Экспорт недоступен, пока результаты устарели, при ошибке расчёта, при
  ошибках валидации и для пустой выборки. Если поиск ещё не успел
  отрисоваться, экспорт сначала применяет актуальный запрос, чтобы файл не
  отстал от поля.

## 4. Ограничения

- Выбранные нити не сохраняются между перезагрузками и не попадают в экспорт:
  ТЗ этапа требует повторного применения после пересчёта и контроля
  актуальности, а не персистентности подбора.
- `sessionStorage` выбран вместо `localStorage`: представление живёт в рамках
  вкладки.
