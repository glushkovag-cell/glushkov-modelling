# Этап 2: понятность и актуальность

Реализация P1-этапа ТЗ «Доработки UI калькулятора такелажа».
Ветка: `feat/rigging-ui-hierarchy`. Расчётное ядро, профили и формулы не
менялись; контрольный снимок `tests/fixtures/rigging-control.json` совпадает.

## 1. Карточки профилей

- Первый уровень карточки всегда показывает название, статус публикации,
  семейство и версию, короткое назначение и главное ограничение профиля.
- Подробности (покрытие, таксономия, калибровка, точность, оговорка, полные
  предупреждения и источники) вынесены в нативный раскрываемый блок
  `Coverage, calibration & sources`. Наведение больше не раскрывает карточку.
- Название и явный выбор профиля не менялись; автоматического подбора по году
  нет.
- Короткое назначение формируется из документа профиля (`family`, название,
  годы), а не дублируется в разметке.
- Общая оговорка об оценочном характере остаётся видимой над формой и в
  подробностях профиля.

## 2. Состояния результатов

Введён явный статус рядом с заголовком и `data-state` на секции результатов:

| Состояние | Ярлык | Поведение |
| --- | --- | --- |
| idle | Not calculated | до первого расчёта |
| calculating | Calculating… | результаты затемнены, `aria-busy`, статус объявляется |
| ready | Current | результаты соответствуют текущему вводу |
| stale | Out of date | ввод изменён; баннер, экспорт отключён |
| error | Error | причина, Retry, экспорт отключён |

- Изменение любого входа сразу помечает результаты устаревшими, но не
  запускает расчёт.
- Баннер устаревания объясняет, что ведомость относится к предыдущему
  расчёту, и содержит кнопку пересчёта.
- Ошибка расчёта показывает причину и Retry, не сбрасывая введённые значения;
  при наличии прошлого расчёта ниже остаётся помеченная старая ведомость.
- Запоздалые ответы по-прежнему отбрасываются по номеру запроса.
- Ошибка загрузки пресета показывается в блоке ошибок формы и не переводит
  результаты в состояние ошибки расчёта.

## 3. Резюме и FIT/ENG

- Над ведомостью добавлена строка «Calculation totals — all N rows before
  filters»: числа относятся ко всему расчёту, а не к текущей выборке.
  Отфильтрованное количество показывается отдельно над ведомостью (`N of M`).
- После релизной полировки это одна компактная строка, а не сетка карточек:
  `All 279 rows · 270 calculated · 0 needs input · 9 unsupported · 0 not applicable`.
- Статусы остаются раздельными; нулевые значения приглушены и не маскируются.
- Отдельные карточки `FIT rows` / `ENG rows` из резюме убраны по замечанию к
  релизу. FIT/ENG остаются маленькими значками в рассчитанных строках
  (группированный вид и плоская таблица) и строкой `Origin` в подробностях.
- У нерассчитанных строк значок происхождения не выводится.

## 4. Подробности строки и переходы к полям

- Подробности по-прежнему раскрываются лениво (кнопкой `Details` в строке) и содержат формулу, базовую
  ссылку, коэффициент, происхождение, материал, точку измерения, диаметр
  прототипа, профиль, источники, предупреждения и идентификаторы.
- Добавлен блок `Base dimensions`: исходный размер, единица, basis, значение
  модели и значение прототипа. Для мачты, бушприта, корпуса и орудия
  показывается соответствующий размер; для якорной группы — все размеры,
  вошедшие в расчёт.
- `Edit base dimension` / `Edit base dimensions` переводит фокус к исходному
  полю формы и подсвечивает строку размера.
- Для строк `needs_input` показывается отсутствующий размер и кнопка
  `Go to the required input`, которая фокусирует первое незаполненное поле.
- Строки `unsupported` показывают причину (`No supported coefficient`) и
  диаметр `—`, а не ноль.

## 5. Отмена смены профиля

- После переключения профиля рядом с выбранным профилем появляется
  `Undo profile change`.
- Снимок содержит полную конфигурацию до переключения (профиль, версия,
  размеры, узлы, паруса), поэтому отмена восстанавливает значения полей, а не
  только название профиля.
- Отмена помечает результаты устаревшими и возвращает фокус на выбранный
  профиль. Сброс формы и загрузка пресета очищают снимок отмены.

## 6. Доступность и диалоги

- Диалог подбора нити удерживает фокус внутри модалки и виджета (включая
  Shadow DOM), закрывается по Escape и возвращает фокус вызвавшей кнопке
  `Pick thread`, а не случайному элементу.
- Баннер устаревания — live-регион, ошибка — `role="alert"`; статус
  результатов не кодируется только цветом.
- Переходы к полям сопровождаются видимой подсветкой строки размера.

- `npm test` — 164 теста, включая контрольный снимок, модель представления,
  состояние, фильтры, поиск и короткие назначения профилей.
- `npx astro check` — 0 ошибок и предупреждений.
- `npm run build` — успешно.
- Браузерная проверка этапа 2 (Chrome headless): **40/40** сценариев, 0
  исключений:
  - карточки профилей: назначение, ограничение, раскрываемые подробности;
  - состояния `idle → calculating → current → stale → error → current`;
  - Retry без потери ввода, экспорт отключён в stale/error;
  - `Base dimensions` и переход к полю;
  - `needs_input` → `Go to the required input`; `unsupported` → причина и `—`;
  - отмена смены профиля восстанавливает значения;
  - фокус-ловушка и возврат фокуса из диалога;
  - карточки профилей и секция результатов без переполнения на 390 px.
- Регрессионный аудит этапа 1: **59/59** сценариев.
- Визуально проверены карточки профилей (1280/390), состояние устаревания,
  ошибка, подробности строки.
